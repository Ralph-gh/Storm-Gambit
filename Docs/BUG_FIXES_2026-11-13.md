# Storm Gambit bug fixes — November 13, 2026

Applied to the existing project, reusing its scenes, prefabs, and assets. No game rebuild or obsolete-script deletion was performed.

## Changes

1. **Hand counts:** starting spells count toward the hand, each draw adds one, and a successful cast removes one exactly once. Cancellation does not remove a card. Checkmate therefore reads the actual remaining count.
2. **Draw isolation:** SoloCardDrawController ignores network turns and completed games. Its existing scene-configured interval is preserved. Multiplayer retains its server draw schedule.
3. **Move transactions:** rejected moves cannot increment MoveNumber or grant cards. The server also checks the selected piece belongs to the requesting side. Accepted promotion moves are counted once.
4. **Server validation:** a shared action gate checks sender/side, current turn, game over, and pending promotion. Spell requests check available resources and the once-per-turn spell allowance. Mage requests check the selected ability and its remaining use. Target-specific checks remain in the individual spell operations.
5. **Confirmed spell consumption:** Teleport, Freeze, Protection, Resurrection, Trap, and Lightning use an accepted/rejected response. Their UIs remain pending until the response and consume the source card or mage ability only on acceptance. A rejected request remains cancellable and retains its resource. Card counts initialize once per match; subsequent resource changes belong to the server.
6. **Rejected move response:** the requesting client receives a result, clears its pending flag, and restores a rejected piece to its authoritative square.
7. **AI recovery:** an engine move rejected by Storm rules falls back to an available Storm-legal classical escape instead of silently leaving the AI turn idle. Frozen/stunned/protected movers and protected capture targets are excluded. Engine-position mismatches and timeouts with a valid escape also recover. This fallback chooses a valid move rather than preserving Stockfish's ranking.

Also corrected the double RPC attribute on Lightning and an AI startup continuation that could access a destroyed component after leaving a scene.

## Script import and compatibility

- `Assets/Scripts/Network/GameStat.cs` was renamed to `GameState.cs` because the class now has a partial implementation in `GameState.NetworkActions.cs`; Unity requires one partial file to match the component class name.
- The original script `.meta` and GUID were preserved: `5de7ad74cf683184f9bf123a6d68df9d`. The regression suite instantiates the existing GameState and NetPlayer prefabs, verifying the GameState component still resolves.
- Existing RPC calls were migrated together. Host and client must use the same updated build; do not mix this version with a previous build.
- A few modified files used a legacy text encoding; they were converted to UTF-8 to edit safely.

## Validation

Unity 6000.3.24f1 batch compilation succeeded. Seven regression tests passed in Unity's EditMode runner, entering Play Mode for the runtime checks:

- Starting hand, drawing, cancellation, successful consumption, and duplicate completion.
- Checkmate while spells remain and after consuming the final spell.
- Invalid/wrong-side/promotion-blocked moves; rejected-piece restoration; one accepted draw grant.
- Wrong spell targets, repeated spells, selected mage validation, one-time mage consumption, and post-game rejection.
- Per-match resource reset without allowing repeated hand synchronization to refill resources.
- Solo draw suppression during networking and normal offline drawing.
- AI fallback skips a frozen piece and returns the turn to the human.

Tests live in `Assets/Tests/Editor/BugFixRegressionTests.cs`. Local test output is in `.utmp/bugfix-tests.xml` and `.utmp/bugfix-tests.log`.

These checks exercise real host-mode RPC execution using the existing network prefabs. They do not constitute a two-device Relay test, Android build/device test, or full visual/cinematic regression. Those remain release validation. Initial local hand composition remains client-generated; this change does not implement a server-owned deck or a full anti-cheat inventory.
